# B12X W4A16 K128/N64 real-weight component gate — 2026-09-09

This is a component result, not end-to-end serving TPS.

## Scope and dispatch

- One SM121 GB10 with the TP=2 API stopped; one real native 0731 TP=2 rank-0
  layer (K=4096, TP-local intermediate=1024, 256 experts, top-k=6).
- M6 DSpark decode shape, fixed activations and routes, four alternating
  repeat medians of 20 CUDA events for each cache state.
- Candidate environment: `VLLM_B12X_W4A16_FORCE_TILE_CONFIG=128,64,128`.
- Dispatch recording proved the candidate changed FC1 from the selected default
  to K128/N64 and two blocks per SM. FC2 retained its legal K64/N128 tile;
  forcing one shared tile across both independently shaped GEMMs is not a
  valid contract.
- Both default and candidate passed the independent FP32 W4A16 oracle. The
  worst candidate mean per-token cosine was 0.99998856, above the 0.9975 gate.

The candidate is about 1.2% faster at this isolated component. This is below
the M6 gate of at least 10% cold-cache improvement needed to justify a costly
TP2 serving A/B toward the 80 TPS target. It was not deployed; native text
service was restored worker-first.

The first tile attempt recorded the same FC1 K128/N64 dispatch but stopped
before timings because the harness incorrectly required FC2 to use that same
tile. The corrected gate explicitly validates the intended FC1 override and
records FC2 separately.
